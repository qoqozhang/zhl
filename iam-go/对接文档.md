## 支持的授权模式

| grant_type            | 说明                         | 适用场景                     |
| --------------------- | ---------------------------- | ---------------------------- |
| `authorization_code`  | 授权码模式（RFC 6749 §4.1）  | 有前端/浏览器的第三方应用    |
| `refresh_token`       | 刷新令牌（RFC 6749 §6）      | 延长 Access Token 生命周期   |
| `client_credentials`  | 客户端凭证模式（RFC 6749 §4.4） | 后端服务间调用，无用户参与 |

> 暂不支持 Implicit 和 Password 模式。

## 接入准备：注册 OAuth 客户端

OAuth 客户端需要由 IAM 系统管理员在后台创建。

### 管理接口

| 方法 | 路径                                                  | 说明              |
| ---- | ----------------------------------------------------- | ----------------- |
| POST | `/v1/oauth/clients`                                   | 创建客户端        |
| GET  | `/v1/oauth/clients`                                   | 列表              |
| GET  | `/v1/oauth/clients/:id`                               | 详情              |
| PUT  | `/v1/oauth/clients/:id`                               | 更新              |
| DELETE | `/v1/oauth/clients/:id`                             | 删除              |
| POST | `/v1/oauth/clients/:id/reset-secret`                  | 重置 client_secret |

> 上述接口均需 **admin 角色** 访问（`Authorization: Bearer {admin_access_token}`）。

### 创建客户端请求示例

```http
POST /v1/oauth/clients HTTP/1.1
Authorization: Bearer {admin_access_token}
Content-Type: application/json

{
  "client_id": "demo_app",
  "client_name": "演示应用",
  "redirect_uris": [
    "https://demo.example.com/callback",
    "http://localhost:3000/callback"
  ],
  "scopes": "openid profile email user:read"
}
```

### 创建客户端响应示例

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "id": 1,
    "client_id": "demo_app",
    "client_secret": "a1b2c3d4...（仅显示一次，请妥善保管）",
    "client_name": "演示应用",
    "redirect_uris": "https://demo.example.com/callback,http://localhost:3000/callback",
    "scopes": "openid profile email user:read",
    "status": 1
  }
}
```

### 字段说明

| 字段           | 类型     | 必填 | 说明                                                         |
| -------------- | -------- | ---- | ------------------------------------------------------------ |
| `client_id`    | string   | 是   | 全局唯一标识，最长 128 字符，建议用英文 + 下划线             |
| `client_name`  | string   | 是   | 展示名称                                                     |
| `redirect_uris`| string[] | 是   | 授权回调地址白名单，**必须完全匹配**                          |
| `scopes`       | string   | 否   | 允许的 scope 列表，空格分隔，如 `openid profile email`       |

## 授权码模式（Authorization Code）

适用于有浏览器/前端的应用（Web SPA、移动 App 等）。

### 流程总览

```
┌──────────┐     ① 访问授权端点      ┌──────────┐
│          │ ──────────────────────► │          │
│          │                         │          │
│   客户端  │                         │  IAM 服务 │
│          │ ◄────────────────────── │          │
│          │     ② 重定向到登录/授权页 │          │
└────┬─────┘                         └──────────┘
     │
     │   用户登录并同意
     ▼
┌──────────┐     ③ 重定向回 redirect_uri（带 code）
│  用户    │ ────────────────────────► ┌──────────┐
│  浏览器  │                          │          │
└──────────┘                          │   客户端  │
                                      │  (后端)  │
                                      └────┬─────┘
                                           │
                                           │ ④ 用 code 换 token
                                           ▼
                                      ┌──────────┐
                                      │  IAM 服务 │
                                      └──────────┘
```

### 第一步：用户登录（获取 Session）

调用 IAM 登录接口，建立登录 Session（写 Cookie）或获取 Access Token。

```http
POST /v1/users/login HTTP/1.1
Content-Type: application/json

{
  "username": "zhangsan",
  "password": "your_password"
}
```

成功后响应头会写入 `iam_session` Cookie，后续 `/oauth2/authorize` 会自动识别。

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "access_token": "eyJhbGciOiJIUzI1NiIs...",
    "refresh_token": "eyJhbGciOiJIUzI1NiIs...",
    "token_type": "Bearer"
  }
}
```

### 第二步：重定向到授权端点

```
GET /oauth2/authorize?client_id={client_id}
    &redirect_uri={redirect_uri}
    &response_type=code
    &scope={scope}
    &state={state}
```

| 参数            | 必填 | 说明                                                    |
| --------------- | ---- | ------------------------------------------------------- |
| `client_id`     | 是   | 已注册的客户端 ID                                       |
| `redirect_uri`  | 是   | 必须完全匹配客户端注册时的 redirect_uris 中的一个       |
| `response_type` | 是   | 固定为 `code`                                           |
| `scope`         | 否   | 覆盖客户端默认 scope，空格分隔                           |
| `state`         | 否   | CSRF 防护，建议必传，回调时原样返回                      |

**已登录** → 服务端直接生成授权码并重定向：

```http
HTTP/1.1 302 Found
Location: https://demo.example.com/callback?code=abc123def456&state=xyz
```

**未登录** → 返回 401 JSON，提示先登录：

```json
{
  "code": 40100,
  "message": "login required, POST /v1/users/login first (creates session cookie)"
}
```

### 第三步：用授权码换取 Access Token

授权码有效期 **5 分钟**，且**一次性**使用。

```http
POST /oauth2/token HTTP/1.1
Content-Type: application/x-www-form-urlencoded

grant_type=authorization_code
&code={code}
&redirect_uri={redirect_uri}
&client_id={client_id}
&client_secret={client_secret}
```

| 参数            | 必填 | 说明                                    |
| --------------- | ---- | --------------------------------------- |
| `grant_type`    | 是   | `authorization_code`                    |
| `code`          | 是   | 第二步拿到的授权码                       |
| `redirect_uri`  | 是   | 必须与授权请求中的值完全一致             |
| `client_id`     | 是   | 客户端 ID                               |
| `client_secret` | 是   | 客户端密钥                              |

> `client_id` / `client_secret` 也可放在 query string 中传递（优先级低于 form）。

**成功响应：**

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "token_type": "Bearer",
  "expires_in": 1800,
  "refresh_token": "eyJhbGciOiJIUzI1NiIs...",
  "scope": "openid profile email"
}
```

## 授权码模式 + PKCE

对于 SPA / 移动端等**无法安全保存 client_secret** 的场景，推荐使用 PKCE（Proof Key for Code Exchange，RFC 7636）。

### 第一步：客户端生成 PKCE 参数

```
code_verifier   = 随机字符串（至少 43 字符，推荐 128 字符）
code_challenge  = BASE64URL(SHA256(code_verifier))
code_challenge_method = S256
```

Node.js 示例：

```js
const crypto = require('crypto');
const codeVerifier = crypto.randomBytes(64).toString('hex');
const codeChallenge = crypto
  .createHash('sha256')
  .update(codeVerifier)
  .digest('base64url')
  .replace(/=+$/, '');
```

### 第二步：带 PKCE 参数发起授权

```
GET /oauth2/authorize?client_id=demo_app
    &redirect_uri=https://demo.example.com/callback
    &response_type=code
    &code_challenge={code_challenge}
    &code_challenge_method=S256
```

### 第三步：换 Token 时带上 code_verifier

```http
POST /oauth2/token HTTP/1.1
Content-Type: application/x-www-form-urlencoded

grant_type=authorization_code
&code={code}
&redirect_uri={redirect_uri}
&client_id=demo_app
&code_verifier={code_verifier}
```

> PKCE 参数在 `/oauth2/token` 端点完成校验，校验失败返回 `invalid_grant`。

### 支持的 code_challenge_method

| 值       | 说明                                  |
| -------- | ------------------------------------- |
| `S256`   | 推荐，SHA-256 + Base64url             |
| `plain`  | 明文回传（不推荐，仅兼容旧客户端）    |

## 客户端凭证模式（Client Credentials）

适用于后端服务间调用，**不涉及用户**，只需要 client_id + client_secret 即可。

```http
POST /oauth2/token HTTP/1.1
Content-Type: application/x-www-form-urlencoded

grant_type=client_credentials
&client_id={client_id}
&client_secret={client_secret}
```

**成功响应：**

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "token_type": "Bearer",
  "expires_in": 1800,
  "scope": "openid profile email"
}
```

> 该模式**不返回 refresh_token**，Access Token 由服务端自己管理过期时间。

## 刷新 Access Token

Access Token 默认有效期 **30 分钟**，过期后用 refresh_token 换新。

```http
POST /oauth2/token HTTP/1.1
Content-Type: application/x-www-form-urlencoded

grant_type=refresh_token
&refresh_token={refresh_token}
&client_id={client_id}
&client_secret={client_secret}
```

| 参数            | 必填 | 说明                                                  |
| --------------- | ---- | ----------------------------------------------------- |
| `grant_type`    | 是   | `refresh_token`                                       |
| `refresh_token` | 是   | 上次换 token 返回的 refresh_token                     |
| `client_id`     | 否   | 带上可额外校验客户端身份                              |
| `client_secret` | 否   | 与 client_id 配套使用                                 |

**成功响应：**

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "token_type": "Bearer",
  "expires_in": 1800
}
```

> Refresh Token 默认有效期 **7 天**，且是**一次性**使用（使用后 Redis 中的 jti 会被删除）。
> 刷新接口**不返回新的 refresh_token**，建议客户端在拿到新 access_token 后，继续保留原 refresh_token（直到过期或撤销）。

## 获取用户信息（UserInfo）

拿到 Access Token 后，可调用 UserInfo 端点获取当前登录用户的标准化信息。

```http
GET /oauth2/userinfo HTTP/1.1
Authorization: Bearer {access_token}
```

**成功响应：**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "user_id": 1,
    "username": "zhangsan",
    "real_name": "张三",
    "email": "zhangsan@example.com",
    "phone": "13800138000",
    "avatar_url": "https://cdn.example.com/avatar/1.png",
    "role_keys": ["user", "admin"],
    "client_id": "demo_app",
    "scope": "openid profile email"
  },
  "request_id": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
}
```

## 错误响应

所有 OAuth 端点遵循 RFC 6749 错误格式，同时包含一个可选的 `request_id` 方便排查。

### 标准错误格式

```json
{
  "error": "{error_code}",
  "error_description": "{error_description}"
}
```

### /oauth2/authorize 错误

当 `redirect_uri` 无效时，服务端会重定向回 `redirect_uri`（如果能取到的话），通过 query 参数返回错误：

```
Location: https://demo.example.com/callback?error={error_code}&error_description={desc}&state={state}
```

### 错误码一览

| HTTP | error                 | 触发场景                                          |
| ---- | --------------------- | ------------------------------------------------- |
| 400  | `invalid_request`     | 缺少必填参数、redirect_uri 不匹配                 |
| 400  | `unsupported_response_type` | response_type 不是 `code`                     |
| 401  | `invalid_client`      | client_id 不存在 / 已禁用 / client_secret 错误     |
| 400  | `invalid_grant`       | code 找不到 / 已使用 / 已过期 / PKCE 校验失败      |
| 400  | `unsupported_grant_type` | grant_type 不支持                              |
| 500  | `server_error`        | 服务端内部错误                                    |

## Token 说明

### Access Token

- 格式：JWT（HS256）
- 有效期：**30 分钟**（可在配置中调整 `jwt.expire_minutes`）
- 签名密钥：`jwt.secret`（生产环境必须配置）
- Claims：

```json
{
  "user_id": 1,
  "username": "zhangsan",
  "role": "admin",
  "client_id": "demo_app",
  "scope": "openid profile email",
  "iss": "iam-go",
  "sub": "1",
  "iat": 1733184000,
  "exp": 1733185800
}
```

### Refresh Token

- 格式：JWT（HS256）
- 有效期：**7 天**（可配置 `jwt.refresh_expire_days`）
- 服务端校验：Redis 中必须存在对应的 `jti`（防撤销）
- 撤销方式：调用 `/v1/users/logout` 时传入 refresh_token，或服务端直接删 Redis key

### 使用 Access Token 访问受保护资源

```http
Authorization: Bearer {access_token}
```

服务端认证优先级：**Session Cookie（iam_session）** > **Bearer Token**。

## 附录：完整端点清单

| 方法  | 路径                    | 认证要求                | 说明                               |
| ----- | ----------------------- | ----------------------- | ---------------------------------- |
| GET   | `/oauth2/authorize`     | 已登录 Session 或 Token | 授权端点（需带限流）               |
| POST  | `/oauth2/token`         | 无（公开）              | 令牌端点，支持 3 种 grant_type     |
| GET   | `/oauth2/userinfo`      | Optional（有凭证就解析）| OIDC UserInfo 端点                 |
| POST  | `/v1/users/login`       | 无                      | 登录（建 Session + 发 Token）      |
| POST  | `/v1/users/refresh`     | 无（传 refresh_token）  | 业务层刷新 Token                   |
| POST  | `/v1/users/logout`      | 可选（传 refresh_token）| 登出（删 Session + 撤销 Refresh）  |
| POST  | `/v1/oauth/clients`     | admin                   | 创建 OAuth 客户端                  |
| GET   | `/v1/oauth/clients`     | admin                   | 客户端列表                         |
| GET   | `/v1/oauth/clients/:id` | admin                   | 客户端详情                         |
| PUT   | `/v1/oauth/clients/:id` | admin                   | 更新客户端                         |
| DELETE| `/v1/oauth/clients/:id` | admin                   | 删除客户端                         |
| POST  | `/v1/oauth/clients/:id/reset-secret` | admin          | 重置 client_secret                 |
