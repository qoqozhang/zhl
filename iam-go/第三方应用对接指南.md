# IAM-Go 第三方应用对接指南

> 本文档面向**第三方应用开发者**，说明如何基于本 IAM 系统完成 OAuth 2.0 对接。
> 
> 如有疑问，请联系 IAM 系统管理员。

---

## 一、双方信息交换清单

### 你方（第三方应用）需要提供给 IAM 管理员

| 信息项          | 是否必填 | 示例                                                    | 说明                                                              |
| --------------- | -------- | ------------------------------------------------------- | ----------------------------------------------------------------- |
| 应用标识        | 是       | `erp_system`                                            | 英文 + 下划线，全局唯一，用于识别你方应用                         |
| 应用名称        | 是       | `ERP 管理系统`                                          | 展示用的中文/英文名称                                             |
| 回调地址（白名单） | 是     | `https://erp.company.com/callback`<br>`http://127.0.0.1:8080/callback` | **必须精确匹配**，可提供多个（数组形式），IAM 只允许在白名单内的地址接收授权码 |
| 申请的 Scope    | 否       | `openid profile email user:read`                        | 需要的用户权限范围，可参考下方 Scope 列表                          |

### IAM 管理员返回给你方的信息

| 信息项            | 说明                                                                     |
| ----------------- | ------------------------------------------------------------------------ |
| `client_id`       | 应用唯一标识，类似 `erp_system`                                          |
| `client_secret`   | **只显示一次**，请立即保存到你方后端配置中。丢失或泄露后请联系管理员重置 |
| 基础地址          | 例如 `https://iam.company.com`                                           |
| 允许的 redirect_uris | 与你方提交的一致，IAM 侧已录入                                           |
| 允许的 scopes     | 与你方申请的一致，实际下发时以此为准                                     |

> 管理员通过以下接口创建客户端（该接口仅 admin 可调用）：
> 
> ```http
> POST /v1/oauth/clients
> Content-Type: application/json
> 
> {
>   "client_id": "erp_system",
>   "client_name": "ERP 管理系统",
>   "redirect_uris": [
>     "https://erp.company.com/callback"
>   ],
>   "scopes": "openid profile email user:read"
> }
> ```
> 
> 管理员拿到 `client_secret` 后发给你方。

## 二、Scope 列表

| Scope          | 说明                                   |
| -------------- | -------------------------------------- |
| `openid`       | 基础用户标识（user_id、username）      |
| `profile`      | 用户资料（real_name、avatar_url）      |
| `email`        | 用户邮箱                               |
| `phone`        | 用户手机号                             |
| `user:read`    | 读取用户列表/详情                      |
| `role:read`    | 读取角色/权限信息                      |

> Scope 以空格分隔，例如 `openid profile email`。未指定时使用客户端注册时的默认值。

## 三、对接方式选择

根据你方应用类型选择合适的模式：

| 你的应用类型         | 推荐模式                      | 是否需要 client_secret | 说明                                 |
| -------------------- | ----------------------------- | ---------------------- | ------------------------------------ |
| 传统 Web 应用（有后端） | 授权码模式 Authorization Code | 是（存后端）           | 最安全，用户体验完整                  |
| SPA / 移动端 App     | 授权码模式 + PKCE             | **不需要**             | 无法安全保存 secret，用 PKCE 替代     |
| 后端服务（无用户）    | 客户端凭证 Client Credentials | 是（存后端）           | 纯服务间调用，Access Token 不绑定用户 |

## 四、对接步骤

### 场景 A：Web 应用（授权码模式）

#### 步骤 1：引导用户到 IAM 登录授权

将用户浏览器重定向到 IAM 授权端点：

```
GET {IAM_BASE}/oauth2/authorize
    ?client_id=erp_system
    &redirect_uri=https://erp.company.com/callback
    &response_type=code
    &scope=openid profile email
    &state=随机字符串（防 CSRF，建议每次不同）
```

参数说明：

| 参数            | 必填 | 值                                          |
| --------------- | ---- | ------------------------------------------- |
| `client_id`     | 是   | IAM 给你的 client_id                        |
| `redirect_uri`  | 是   | **必须完全匹配**注册时的某个地址            |
| `response_type` | 是   | 固定 `code`                                 |
| `scope`         | 否   | 不填则使用注册时的默认 scope                |
| `state`         | 强烈建议 | 任意字符串，回调时原样返回，用于校验        |

#### 步骤 2：用户登录并授权

IAM 会展示登录页面，用户输入账号密码后，IAM 会自动完成授权（当前版本默认不需要单独的"同意页"）。

#### 步骤 3：IAM 重定向回你方

成功后 IAM 会带着 `code` 重定向到你方的 `redirect_uri`：

```
https://erp.company.com/callback?code=a1b2c3d4e5f6...&state=你传入的state
```

| 返回参数 | 说明                                                     |
| -------- | -------------------------------------------------------- |
| `code`   | 授权码，**5 分钟有效、一次性**，拿到后立即换 token       |
| `state`  | 原样返回，**务必与步骤 1 对比**，防止 CSRF 攻击          |

如果出错，IAM 会这样返回：

```
https://erp.company.com/callback?error=invalid_request&error_description=redirect_uri+not+registered&state=xxx
```

错误码见文末附录。

#### 步骤 4：后端用 code 换 token

**这个请求必须在你方后端发起**（因为要带 client_secret），不要放在前端。

```http
POST {IAM_BASE}/oauth2/token
Content-Type: application/x-www-form-urlencoded

grant_type=authorization_code
&code=步骤3拿到的code
&redirect_uri=https://erp.company.com/callback
&client_id=erp_system
&client_secret=IAM给你的client_secret
```

**成功响应：**

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "token_type": "Bearer",
  "expires_in": 1800,
  "refresh_token": "eyJhbGciOiJIUzI1NiIs...",
  "scope": "openid profile email"
}
```

| 字段            | 说明                                    |
| --------------- | --------------------------------------- |
| `access_token`  | **Bearer Token**，后续调用接口时使用   |
| `token_type`    | 固定 `Bearer`                           |
| `expires_in`    | Access Token 剩余秒数，固定 **1800**    |
| `refresh_token` | 用于续期 Access Token，有效期 **7 天**  |
| `scope`         | 实际生效的 scope 列表                  |

#### 步骤 5：调用 UserInfo 获取用户身份

拿到 access_token 后，你方后端或前端可以用它向 IAM 换取用户信息：

```http
GET {IAM_BASE}/oauth2/userinfo
Authorization: Bearer 你的access_token
```

**响应：**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "user_id": 1,
    "username": "zhangsan",
    "real_name": "张三",
    "email": "zhangsan@example.com",
    "phone": "13800138000",
    "avatar_url": "https://cdn.company.com/avatar/1.png",
    "role_keys": ["user"],
    "client_id": "erp_system",
    "scope": "openid profile email"
  }
}
```

你方拿到 `user_id` 或 `username` 后，就可以和你方本地用户做关联（首次授权时建议自动创建账号）。

#### 步骤 6：续期 Access Token

Access Token 30 分钟就过期了。过期后，用 refresh_token 换新：

```http
POST {IAM_BASE}/oauth2/token
Content-Type: application/x-www-form-urlencoded

grant_type=refresh_token
&refresh_token=你保存的refresh_token
&client_id=erp_system
&client_secret=你的client_secret
```

**响应：**

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...（新的）",
  "token_type": "Bearer",
  "expires_in": 1800
}
```

> ⚠️ Refresh Token 是**一次性**的，使用后旧的就作废了。建议在客户端持久化保存 refresh_token，每次 access_token 过期时用它换新。如果 refresh_token 也过期了，就需要让用户重新走授权流程。

#### 步骤 7：登出（可选）

用户在你方系统登出时，如希望同时注销 IAM 的登录态：

```http
POST {IAM_BASE}/v1/users/logout
Content-Type: application/json

{
  "refresh_token": "你保存的refresh_token"
}
```

### 场景 B：SPA / 移动端（PKCE 模式）

PKCE 模式**不需要 client_secret**，全程在前端即可完成。

#### 步骤 1：前端生成 PKCE 参数

```js
// Node.js / 浏览器环境
const crypto = window.crypto || require('crypto');

// code_verifier：随机字符串，至少 43 字符
const array = new Uint8Array(32);
crypto.getRandomValues(array);
const codeVerifier = Array.from(array, b => b.toString(16).padStart(2, '0')).join('');

// code_challenge = BASE64URL(SHA256(code_verifier))
const hash = await crypto.subtle.digest('SHA-256', new TextEncoder().encode(codeVerifier));
const codeChallenge = btoa(String.fromCharCode(...new Uint8Array(hash)))
  .replace(/\+/g, '-').replace(/\//g, '_').replace(/=+$/, '');
```

#### 步骤 2：带 PKCE 参数跳转到授权

```
GET {IAM_BASE}/oauth2/authorize
    ?client_id=erp_spa
    &redirect_uri=https://erp.company.com/callback
    &response_type=code
    &code_challenge={上一步生成的code_challenge}
    &code_challenge_method=S256
    &state=随机字符串
```

#### 步骤 3：拿到 code 后，前端直接换 token

```http
POST {IAM_BASE}/oauth2/token
Content-Type: application/x-www-form-urlencoded

grant_type=authorization_code
&code=回调拿到的code
&redirect_uri=https://erp.company.com/callback
&client_id=erp_spa
&code_verifier=步骤1生成的code_verifier
```

> ⚠️ 注意这里**不传 client_secret**，而是传 `code_verifier`。IAM 会用它和授权时的 `code_challenge` 做 SHA-256 比对。

后续 UserInfo、刷新 Token 流程与场景 A 相同，只是刷新时也不需要 client_secret。

---

### 场景 C：后端服务（客户端凭证模式）

适用于无用户参与的服务间调用，例如你方定时任务需要访问 IAM 接口。

```http
POST {IAM_BASE}/oauth2/token
Content-Type: application/x-www-form-urlencoded

grant_type=client_credentials
&client_id=erp_system
&client_secret=你的client_secret
```

**响应：**

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "token_type": "Bearer",
  "expires_in": 1800,
  "scope": "openid profile email"
}
```

> 该模式**不返回 refresh_token**，需要你方在 Access Token 到期前主动重新调用 token 接口获取新的。

## 五、HTTP 调用的完整示例（cURL）

```bash
# ===== 1. 引导用户授权（浏览器访问）=====
# 打开浏览器访问（或前端重定向）：
# https://iam.company.com/oauth2/authorize?client_id=erp_system&redirect_uri=https://erp.company.com/callback&response_type=code&scope=openid%20profile&state=abc123

# ===== 2. 用 code 换 token（后端调用）=====
curl -X POST https://iam.company.com/oauth2/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=authorization_code" \
  -d "code=a1b2c3d4e5f6..." \
  -d "redirect_uri=https://erp.company.com/callback" \
  -d "client_id=erp_system" \
  -d "client_secret=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"

# ===== 3. 用 access_token 获取用户信息 =====
curl https://iam.company.com/oauth2/userinfo \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIs..."

# ===== 4. 刷新 token =====
curl -X POST https://iam.company.com/oauth2/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=refresh_token" \
  -d "refresh_token=eyJhbGciOiJIUzI1NiIs..." \
  -d "client_id=erp_system" \
  -d "client_secret=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
```

## 六、附录

### 端点地址汇总

| 端点       | URL 格式                          |
| ---------- | --------------------------------- |
| 授权端点   | `{IAM_BASE}/oauth2/authorize`    |
| Token 端点 | `{IAM_BASE}/oauth2/token`         |
| UserInfo   | `{IAM_BASE}/oauth2/userinfo`      |
| 业务登录   | `{IAM_BASE}/v1/users/login`       |
| 业务登出   | `{IAM_BASE}/v1/users/logout`     |

### 错误码

| HTTP | error                 | 含义                                       | 排查方向                               |
| ---- | --------------------- | ------------------------------------------ | -------------------------------------- |
| 400  | `invalid_request`     | 缺少必填参数 / redirect_uri 不匹配         | 检查参数是否齐全、redirect_uri 是否完全匹配 |
| 400  | `unsupported_response_type` | response_type 不是 `code`            | 改为 `response_type=code`              |
| 401  | `invalid_client`      | client_id 不存在 / 已禁用 / secret 错误     | 核对 client_id 和 client_secret       |
| 400  | `invalid_grant`       | code 无效 / 已使用 / 已过期 / PKCE 失败    | code 只能用一次、5 分钟内要用掉、PKCE 参数是否正确 |
| 400  | `unsupported_grant_type` | grant_type 写错                        | 检查拼写                               |
| 500  | `server_error`        | IAM 内部错误                                | 联系管理员，提供 response 中的 `request_id` |

### 常见问题

**Q：redirect_uri 必须精确匹配吗？尾部斜杠、查询参数不一样可以吗？**
A：必须**完全相同**的字符串匹配。`https://a.com/callback` 和 `https://a.com/callback/` 是两个不同地址。

**Q：client_secret 丢了怎么办？**
A：联系 IAM 管理员调用重置接口，会返回一个新的明文 secret（同样只显示一次）。

**Q：Access Token 过期后还能用吗？**
A：不能。过期后服务端会返回 401，此时必须用 refresh_token 换新。

**Q：Refresh Token 可以一直用吗？**
A：不行。单次有效期 7 天，且每次使用后旧的就作废了。如果 refresh_token 也过期，需要用户重新登录授权。

**Q：如何撤销某个 refresh_token？**
A：调用 `/v1/users/logout` 时传入该 refresh_token 即可。

**Q：返回的 `request_id` 是什么？**
A：每次请求的唯一标识，出问题时把它发给管理员可以快速定位日志。
